# 식재료 가격 자동 환산

가격 수집 API와 기존 주간 수집에 자동 환산을 연결했습니다. 새 백엔드 버전을 배포하면 기존 `KAMIS`와 이번에 추가한 `KAMIS_PORTFOLIO` 시계열이 모두 자동 수집 대상에 포함됩니다.

## 처리 순서

1. 시계열의 도매/소매 구분에 맞는 KAMIS API를 호출합니다. 축산 부류(500)는 소매 API를 사용합니다.
2. 해당 지역의 실제 조사 행을 선택합니다. 저장된 시장이 있으면 그 시장을 우선하고, 대표가격 시계열은 여러 시장의 평균을 사용합니다.
3. 응답 `kindname`의 마지막 단위를 읽습니다. `20kg(1kg)`은 1kg, `목심(100g)`은 100g, `애호박(20개)`는 개수 기준으로 환산합니다.
4. 원/g 가격을 일관되게 계산할 수 있도록 1kg 환산 가격과 기준 중량 1,000g으로 저장합니다.
5. 기존 승인 매핑의 조리·가식부 계수는 유지합니다. 지원하는 새 식재료에 매핑이 없으면 대표 품목과 조리 상태를 확인해 계수를 자동 계산하여 추가합니다.
6. 수집 배치 완료 후 메뉴 원가 캐시를 다시 읽어 최신 가격을 반영합니다.

가격 수집 단계에서는 구매 단위만 환산하고, 메뉴 원가 계산 단계에서 `ingredient_price_mapping.conversion_factor`를 한 번 적용합니다. 조리 수율을 가격 저장과 메뉴 계산에서 중복 적용하지 않습니다.

## 환산 기준 수정

공통 설정 파일은 `src/main/resources/portfolio-price-rules.json`입니다. 백엔드와 Python 가격 갱신 스크립트가 같은 파일을 사용합니다.

- `rootItems`: 식재료 기본 이름과 KAMIS 품목 코드.
- `eachGrams`: 품목별 개당 대표 중량. 애호박 350g, 오이 200g, 달걀 가식부 50g, 김 1장 2.5g 등.
- `factors`: 우유 밀도, 조리 수율, 가식부 비율, 건조/수화 비율 등.
- `excludedWords`: 잼·통조림·가공우유 등 자동 연결에서 제외할 가공 상태.

지원하지 않는 단위·개당 중량·밀도는 로그를 남기고 저장하지 않습니다. 새 품목은 환산 기준과 KAMIS 시계열을 등록한 뒤 수집하면 됩니다. API가 제공하지 않는 식재료의 가격을 자동 생성하지는 않습니다.

자동 매핑은 포트폴리오용 대표가격입니다. 기존 승인·거절 결정은 덮어쓰지 않고, 이미 제안된 동일 연결도 자동으로 승인하지 않습니다. 기존 매핑의 계수는 설정 파일을 바꿔도 자동 변경되지 않습니다. 필요한 경우 검토 후 기존 매핑을 별도로 수정해야 합니다.

## 사용

기존 `POST /api/prices/kamis/collect/{ingredientCode}?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` 수집 경로에서 자동 처리됩니다. 승인된 매핑이 가리키는 시계열도 찾으므로 대표가격 소유 식재료와 다른 코드로 요청해도 수집할 수 있습니다.

주간 수집은 기존 `KAMIS_COLLECTION_SCHEDULE_CRON`과 `KAMIS_COLLECTION_LOOKBACK_DAYS` 설정을 사용합니다. 별도 외부 자동화를 만들 필요가 없습니다. 새 코드 배포 전의 AWS 백엔드에는 이 변경이 적용되지 않습니다.

검증은 실제 DB를 변경하지 않는 단위 테스트와 메모리 DB 통합 테스트로 수행합니다.
